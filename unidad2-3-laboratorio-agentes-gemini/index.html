Laboratorio de Agentes de IA — Unidad 2.3 (con Gemini real)

Universidad de Caldas

Material de apoyo practico para la Unidad 2.3 (Agentes de Inteligencia Artificial) del curso Estrategias de Transformacion Digital.

Este notebook usa un modelo de lenguaje real: Gemini, de Google, a traves del SDK oficial google-genai. Para ejecutarlo se necesita una API key gratuita, que se obtiene en https://aistudio.google.com/apikey (Google ofrece una cuota gratuita mensual suficiente para todos los ejercicios de este notebook).

Como obtener y usar la API key:

  • En Google Colab: Herramientas > Secretos (icono de llave en el panel izquierdo), crear un secreto llamado GEMINI_API_KEY con el valor de la llave, y darle acceso a este notebook. El codigo de la siguiente celda ya esta escrito para leerlo asi.

  • En una maquina local (fuera de Colab): se pedira la llave de forma interactiva y oculta (no queda escrita en el notebook).

Contenido:

  1. Instalacion, API key y primera llamada de prueba

  2. Tool calling manual: un agente que reprograma citas medicas

  3. Tool calling automatico: la misma tarea, con el SDK manejando el ciclo

  4. Grounding real: un agente investigador con acceso a Google Search

  5. Sistema multiagente real: un reporte de inteligencia de mercado

  6. Salida estructurada (JSON) para un flujo tipo n8n

  7. Riesgos en la practica: una alucinacion real y control humano antes de actuar

# Instala el SDK oficial de Google para Gemini (reemplaza al antiguo google-generativeai, ya descontinuado)

import os  # para leer variables de entorno
import json  # para trabajar con las respuestas en formato JSON de la seccion 6

from google import genai  # cliente principal del SDK
from google.genai import types  # tipos auxiliares: Tool, GenerateContentConfig, Part, etc.

# --- Obtencion de la API key, de forma distinta segun el entorno ---
try:
    from google.colab import userdata  # este import solo funciona dentro de Google Colab
    api_key = userdata.get("GEMINI_API_KEY")  # lee la llave guardada en los Secretos de Colab
except ImportError:
    import getpass  # libreria estandar para pedir texto sin mostrarlo en pantalla
    api_key = os.environ.get("GEMINI_API_KEY") or getpass.getpass("Pega tu API key de Gemini: ")  # usa la variable de entorno si existe, o la pide de forma oculta

client = genai.Client(api_key=api_key)  # crea el cliente autenticado con la API key obtenida

MODELO = "gemini-3.8-flash"  # modelo rapido y economico, adecuado para los ejercicios de este notebook

# Llamada de prueba simple, sin herramientas, solo para confirmar que la API key funciona
respuesta_prueba = client.models.generate_content(
    model=MODELO,  # modelo que se va a usar
    contents="Responde en una sola oracion: que es un agente de inteligencia artificial?",  # prompt de prueba
)

print(respuesta_prueba.text)  # muestra el texto de la respuesta del modelo

2. Tool calling manual: un agente que reprograma citas medicas¶

Se reproduce el ejemplo del texto guia: un agente que necesita consultar la cita actual de un paciente, consultar la disponibilidad de horarios, y confirmar el cambio. Aqui se implementa el ciclo de tool calling de forma manual y explicita, para que se vea con claridad la separacion entre lo que decide el modelo y lo que ejecuta el codigo: el modelo nunca toca directamente la base de datos de citas, solo decide que herramienta usar y con que parametros.

# "Base de datos" en memoria, simulando el sistema de agendamiento de una clinica
citas_pacientes = {
    "paciente_001": {"dia": "jueves", "hora": "10:00"},  # cita actual del paciente simulado
}
horarios_disponibles_proxima_semana = ["lunes 09:00", "martes 14:00", "miercoles 11:00"]  # horarios libres simulados


def consultar_cita(id_paciente: str) -> dict:
    """Consulta la cita actual de un paciente en el sistema de agendamiento.

    Args:
        id_paciente: identificador del paciente, por ejemplo 'paciente_001'.
    """
    return citas_pacientes.get(id_paciente, {})  # devuelve la cita registrada, o un diccionario vacio si no existe


def consultar_disponibilidad() -> list:
    """Consulta los horarios disponibles para citas la proxima semana."""
    return list(horarios_disponibles_proxima_semana)  # devuelve una copia de la lista de horarios libres


def confirmar_cambio(id_paciente: str, nuevo_horario: str) -> dict:
    """Confirma el cambio de horario de un paciente, modificando el sistema de agendamiento.

    Args:
        id_paciente: identificador del paciente cuya cita se va a cambiar.
        nuevo_horario: el nuevo horario elegido, en formato 'dia hora', por ejemplo 'lunes 09:00'.
    """
    dia, hora = nuevo_horario.split(" ")  # separa el texto "lunes 09:00" en dia y hora
    citas_pacientes[id_paciente] = {"dia": dia, "hora": hora}  # sobrescribe la cita del paciente con el nuevo horario
    if nuevo_horario in horarios_disponibles_proxima_semana:  # si el horario sigue estando en la lista de disponibles
        horarios_disponibles_proxima_semana.remove(nuevo_horario)  # lo retira, porque ya quedo ocupado
    return citas_pacientes[id_paciente]  # devuelve la cita ya actualizada


# Prueba directa de las funciones, sin IA de por medio, solo para confirmar que la logica basica funciona
print(consultar_cita("paciente_001"))
print(consultar_disponibilidad())

# Declaraciones de las herramientas, en el formato que Gemini necesita para decidir cuando usarlas.
# El "name" y los "parameters" deben coincidir exactamente con las funciones de Python reales.
herramienta_consultar_cita = {
    "name": "consultar_cita",
    "description": "Consulta la cita medica actual de un paciente.",
    "parameters": {
        "type": "object",
        "properties": {
            "id_paciente": {"type": "string", "description": "Identificador del paciente."},
        },
        "required": ["id_paciente"],
    },
}

herramienta_consultar_disponibilidad = {
    "name": "consultar_disponibilidad",
    "description": "Consulta los horarios disponibles para citas la proxima semana.",
    "parameters": {"type": "object", "properties": {}},  # esta herramienta no necesita ningun parametro
}

herramienta_confirmar_cambio = {
    "name": "confirmar_cambio",
    "description": "Confirma el cambio de horario de la cita de un paciente a un nuevo horario.",
    "parameters": {
        "type": "object",
        "properties": {
            "id_paciente": {"type": "string", "description": "Identificador del paciente."},
            "nuevo_horario": {"type": "string", "description": "Nuevo horario elegido, formato 'dia hora', por ejemplo lunes 09:00."},
        },
        "required": ["id_paciente", "nuevo_horario"],
    },
}

# Diccionario que conecta el nombre de cada herramienta con la funcion real de Python que la ejecuta
funciones_disponibles = {
    "consultar_cita": consultar_cita,
    "consultar_disponibilidad": consultar_disponibilidad,
    "confirmar_cambio": confirmar_cambio,
}

conjunto_herramientas = types.Tool(function_declarations=[
    herramienta_consultar_cita,
    herramienta_consultar_disponibilidad,
    herramienta_confirmar_cambio,
])
configuracion_con_herramientas = types.GenerateContentConfig(tools=[conjunto_herramientas])  # empaqueta las herramientas en la configuracion de la llamada

def ejecutar_agente_manual(mensaje_inicial, maximo_pasos=6):
    """Implementa manualmente el ciclo de tool calling: le pregunta al modelo, si pide
    una herramienta la ejecuta de verdad, le devuelve el resultado, y repite hasta que
    el modelo responda con texto final en lugar de pedir otra herramienta.
    """
    historial_conversacion = [
        types.Content(role="user", parts=[types.Part(text=mensaje_inicial)])  # primer mensaje del usuario
    ]

    for paso in range(maximo_pasos):  # limite de seguridad para evitar un ciclo infinito
        respuesta = client.models.generate_content(
            model=MODELO,
            contents=historial_conversacion,  # se envia toda la conversacion acumulada hasta ahora
            config=configuracion_con_herramientas,  # con las herramientas disponibles
        )

        parte_respuesta = respuesta.candidates[0].content.parts[0]  # primera parte de la respuesta del modelo
        historial_conversacion.append(respuesta.candidates[0].content)  # se agrega la respuesta del modelo al historial

        if not parte_respuesta.function_call:  # si el modelo ya no esta pidiendo usar una herramienta
            return respuesta.text  # se devuelve la respuesta final en texto

        llamada = parte_respuesta.function_call  # la herramienta que el modelo quiere usar
        nombre_funcion = llamada.name  # nombre de la herramienta solicitada
        argumentos = dict(llamada.args)  # parametros que el modelo decidio enviarle a la herramienta

        print(f"Paso {paso}: el modelo pide usar '{nombre_funcion}' con argumentos {argumentos}")  # muestra la decision del modelo

        funcion_real = funciones_disponibles[nombre_funcion]  # busca la funcion de Python real correspondiente
        resultado_real = funcion_real(**argumentos)  # EJECUTA la funcion real, con los argumentos que el modelo decidio
        print(f"  Resultado real de la herramienta: {resultado_real}")  # muestra lo que la herramienta realmente devolvio

        # Se empaqueta el resultado real como un mensaje de tipo "function_response", y se agrega al historial
        parte_resultado = types.Part.from_function_response(
            name=nombre_funcion,
            response={"resultado": resultado_real},
        )
        historial_conversacion.append(types.Content(role="user", parts=[parte_resultado]))  # el modelo vera este resultado en el siguiente paso

    return "El agente no termino la tarea dentro del limite de pasos permitido."

resultado_final = ejecutar_agente_manual(
    "Hola, soy el paciente_001 y necesito mover mi cita del jueves para la proxima semana. "
    "Por favor revisa mi cita actual, la disponibilidad, y confirma el cambio al primer horario que encuentres libre."
)

print("\nRespuesta final del agente:")
print(resultado_final)

print("\nEstado final del sistema de agendamiento:")
print(citas_pacientes)  # confirma que la base de datos simulada realmente quedo modificada

3. Tool calling automatico: la misma tarea, con el SDK manejando el ciclo¶

El SDK de Gemini puede manejar automaticamente el ciclo que se acaba de construir a mano: si se le pasan directamente las funciones de Python (con type hints y docstring, como ya estan escritas arriba), el SDK las convierte el mismo en declaraciones de herramientas, detecta cuando el modelo las pide, las ejecuta, y le devuelve el resultado — todo dentro de una sola llamada. Es exactamente el mismo mecanismo de la seccion 2, solo que automatizado.

configuracion_automatica = types.GenerateContentConfig(
    tools=[consultar_cita, consultar_disponibilidad, confirmar_cambio],  # se pasan las funciones de Python directamente, no declaraciones manuales
)

respuesta_automatica = client.models.generate_content(
    model=MODELO,
    contents=(
        "Soy el paciente_001. Revisa mi cita actual, la disponibilidad de la proxima semana, "
        "y confirma el cambio al primer horario disponible."
    ),
    config=configuracion_automatica,  # el SDK maneja todo el ciclo de tool calling internamente
)

print(respuesta_automatica.text)  # muestra directamente la respuesta final, ya con las herramientas ejecutadas por dentro

4. Grounding real: un agente investigador con acceso a Google Search¶

Ademas de herramientas propias, Gemini ofrece herramientas incorporadas, como el acceso a busqueda real en Google (a esto se le llama “grounding”: anclar la respuesta del modelo a informacion real y verificable, en lugar de depender solo de lo que el modelo recuerda de su entrenamiento). Esto se usara en la seccion 5 como el agente investigador de un sistema multiagente.

herramienta_busqueda = types.Tool(google_search=types.GoogleSearch())  # herramienta incorporada de busqueda real en Google
configuracion_busqueda = types.GenerateContentConfig(tools=[herramienta_busqueda])

respuesta_investigacion = client.models.generate_content(
    model=MODELO,
    contents="Busca y resume en 3 frases el estado actual del mercado fintech en Colombia en 2026.",
    config=configuracion_busqueda,
)

print(respuesta_investigacion.text)  # resumen generado a partir de resultados de busqueda reales, no solo memoria del modelo

# La respuesta incluye metadatos sobre que busquedas y fuentes reales uso el modelo para fundamentar la respuesta
metadatos_fundamentacion = respuesta_investigacion.candidates[0].grounding_metadata
if metadatos_fundamentacion and metadatos_fundamentacion.grounding_chunks:  # si el modelo efectivamente encontro fuentes
    print("\nFuentes reales usadas:")
    for fragmento in metadatos_fundamentacion.grounding_chunks:  # recorre cada fuente que el modelo consulto
        print("-", fragmento.web.title, "->", fragmento.web.uri)  # muestra el titulo y el enlace de cada fuente

5. Sistema multiagente real: un reporte de inteligencia de mercado¶

Se reproduce el ejemplo del texto guia, pero ahora con cuatro llamadas reales a Gemini, cada una con un system_instruction distinto que define el rol de ese agente: un investigador (con grounding real de Google Search), un analista, un redactor, y un revisor que verifica que el reporte final no contenga cifras que el investigador nunca encontro.

def llamar_agente(rol_sistema, mensaje_usuario, con_busqueda=False):
    """Hace una llamada a Gemini con un rol (system_instruction) especifico para un agente.

    con_busqueda: si es True, le da a este agente acceso a la herramienta de Google Search.
    """
    configuracion = types.GenerateContentConfig(
        system_instruction=rol_sistema,  # define el rol y las reglas que este agente debe seguir
        tools=[types.Tool(google_search=types.GoogleSearch())] if con_busqueda else None,  # herramienta de busqueda, solo si se solicita
    )
    respuesta = client.models.generate_content(
        model=MODELO,
        contents=mensaje_usuario,
        config=configuracion,
    )
    return respuesta.text  # devuelve solo el texto de la respuesta de este agente


def agente_investigador_real(tema):
    """Agente investigador: busca informacion real sobre el tema solicitado."""
    return llamar_agente(
        rol_sistema="Eres un investigador de mercado. Responde solo con hechos concretos y cifras, sin opiniones.",
        mensaje_usuario=f"Busca datos recientes y concretos sobre: {tema}",
        con_busqueda=True,  # este agente SI tiene acceso a busqueda real
    )


def agente_analista_real(datos_investigacion):
    """Agente analista: organiza los datos crudos en hallazgos claros."""
    return llamar_agente(
        rol_sistema="Eres un analista de datos. Organiza la informacion recibida en 3 hallazgos breves y claros, en una lista.",
        mensaje_usuario=datos_investigacion,
    )


def agente_redactor_real(hallazgos):
    """Agente redactor: convierte los hallazgos en un reporte ejecutivo breve."""
    return llamar_agente(
        rol_sistema="Eres un redactor ejecutivo. Convierte los hallazgos recibidos en un parrafo breve, profesional y directo.",
        mensaje_usuario=hallazgos,
    )


def agente_revisor_real(reporte, datos_originales_investigacion):
    """Agente revisor: verifica que el reporte no incluya cifras que el investigador no respaldo."""
    return llamar_agente(
        rol_sistema=(
            "Eres un revisor de calidad. Compara el REPORTE contra los DATOS ORIGINALES. "
            "Si el reporte menciona alguna cifra o dato que NO aparece en los datos originales, "
            "responde 'RECHAZADO' y explica cual cifra no tiene respaldo. Si todo esta respaldado, responde 'APROBADO'."
        ),
        mensaje_usuario=f"DATOS ORIGINALES:\n{datos_originales_investigacion}\n\nREPORTE:\n{reporte}",
    )


def orquestador_real(tema):
    """Coordina el orden de ejecucion de los cuatro agentes."""
    datos = agente_investigador_real(tema)  # paso 1: investigar con busqueda real
    print("Investigacion:\n", datos, "\n")

    hallazgos = agente_analista_real(datos)  # paso 2: organizar los datos en hallazgos
    print("Hallazgos:\n", hallazgos, "\n")

    reporte = agente_redactor_real(hallazgos)  # paso 3: redactar el reporte final
    print("Reporte:\n", reporte, "\n")

    revision = agente_revisor_real(reporte, datos)  # paso 4: revisar el reporte contra los datos originales
    print("Revision:\n", revision)

    return {"datos": datos, "hallazgos": hallazgos, "reporte": reporte, "revision": revision}

resultado_multiagente = orquestador_real("adopcion de inteligencia artificial en pymes colombianas")  # ejecuta el sistema multiagente completo sobre un tema real

6. Salida estructurada (JSON) para un flujo tipo n8n¶

Para que un agente se integre de forma confiable dentro de un flujo como el de n8n (seccion 6 del texto guia), normalmente no basta con que responda en texto libre: se le pide una salida en un formato estructurado (JSON) que el resto del flujo pueda procesar automaticamente. Gemini permite forzar esto directamente, indicando un esquema de respuesta.

catalogo_precios = {"laptop": 2_500_000, "monitor": 650_000, "teclado": 120_000}  # catalogo simulado de precios

esquema_extraccion = {
    "type": "object",
    "properties": {
        "productos_solicitados": {
            "type": "array",
            "items": {"type": "string"},
            "description": "Lista de nombres de productos mencionados en el correo, usando exactamente los nombres del catalogo.",
        },
    },
    "required": ["productos_solicitados"],
}

configuracion_json = types.GenerateContentConfig(
    response_mime_type="application/json",  # obliga a que la respuesta sea JSON valido
    response_schema=esquema_extraccion,  # y que siga exactamente esta estructura
)

correo_cliente = "Hola, quisiera cotizar un laptop y un monitor para mi oficina, gracias."  # correo de ejemplo de un cliente

respuesta_extraccion = client.models.generate_content(
    model=MODELO,
    contents=f"Extrae los productos mencionados en este correo, usando solo nombres del catalogo {list(catalogo_precios.keys())}: {correo_cliente}",
    config=configuracion_json,
)

datos_extraidos = json.loads(respuesta_extraccion.text)  # convierte el texto JSON devuelto en un diccionario real de Python
print(datos_extraidos)

# El resto del flujo tipo n8n continua en Python normal, igual que en el ejercicio anterior,
# ahora alimentado por la extraccion real que hizo el modelo
productos_cotizados = {p: catalogo_precios[p] for p in datos_extraidos["productos_solicitados"] if p in catalogo_precios}  # cruza los productos extraidos con el catalogo

lineas_cotizacion = [f"{producto}: ${precio:,}" for producto, precio in productos_cotizados.items()]  # formatea cada linea de la cotizacion
respuesta_para_el_cliente = "Cotizacion:\n" + "\n".join(lineas_cotizacion)  # ensambla el texto final de respuesta

print(respuesta_para_el_cliente)

7. Riesgos en la practica: una alucinacion real y control humano antes de actuar¶

Con un modelo real se puede observar una alucinacion real: al preguntarle algo que no tiene forma de saber con certeza (y sin darle acceso a una herramienta de busqueda), el modelo puede responder con una cifra que suena convincente pero que no tiene ningun respaldo. Tambien se muestra como anadir un paso de confirmacion humana obligatoria antes de ejecutar una accion irreversible.

# Se le pregunta algo muy especifico y poco probable que el modelo conozca con certeza,
# y a proposito SIN darle acceso a ninguna herramienta de busqueda
respuesta_riesgo = client.models.generate_content(
    model=MODELO,
    contents="Dime el numero exacto de empleados que tiene hoy la empresa Activos por Colombia.",
)

print(respuesta_riesgo.text)

print(
    "\nSi el modelo respondio con un numero especifico sin aclarar que no tiene forma de "
    "saberlo con certeza, eso es una alucinacion: una respuesta que suena precisa y "
    "segura, pero que no tiene ningun respaldo real detras. La defensa, otra vez, es "
    "obligar al agente a basarse en una herramienta real (como se hizo en la seccion 4 "
    "con Google Search) en lugar de confiar en lo que el modelo 'recuerda', y revisar "
    "sistematicamente cualquier cifra citada antes de usarla para una decision de "
    "negocio."
)

def confirmar_cambio_con_aprobacion_humana(id_paciente, nuevo_horario, aprobado_por_humano=False):
    """Version seguida de la herramienta de confirmacion de citas, usada en la seccion 2.

    Esta version exige una aprobacion humana explicita antes de ejecutar la accion real,
    como medida de control sobre una accion irreversible.
    """
    if not aprobado_por_humano:  # si nadie aprobo explicitamente el cambio
        return "accion bloqueada: se requiere aprobacion humana antes de confirmar el cambio de cita"
    return confirmar_cambio(id_paciente, nuevo_horario)  # si fue aprobado, se ejecuta la accion real


print(confirmar_cambio_con_aprobacion_humana("paciente_001", "martes 14:00"))  # sin aprobacion: la accion queda bloqueada
print(confirmar_cambio_con_aprobacion_humana("paciente_001", "martes 14:00", aprobado_por_humano=True))  # con aprobacion: se ejecuta normalmente

Cierre¶

Este notebook mostro, con un modelo real (Gemini) en lugar de una simulacion, la mecanica completa de los temas de la Unidad 2.3: tool calling manual y automatico, grounding con una herramienta incorporada de busqueda real, un sistema multiagente con cuatro llamadas reales coordinadas por un orquestador, salida estructurada en JSON para integrarse en un flujo tipo n8n, y dos riesgos reales (una alucinacion observada directamente, y una herramienta protegida con confirmacion humana).

Para el proyecto final, el ejercicio equivalente es tomar una de estas plantillas de agente (tool calling, grounding, o sistema multiagente) y adaptarla a un proceso real de la organizacion elegida, usando las herramientas (funciones de Python) que ese proceso realmente necesitaria.
